## Base URL

```
https://api.auth-agent.com
```

## Authentication

Auth Agent uses OAuth 2.1 with PKCE (Proof Key for Code Exchange) for secure authorization. All API endpoints require proper authentication as described in their respective documentation.

## OAuth Endpoints

Public endpoints implementing the OAuth 2.1 standard:

| Endpoint | Method | Purpose |
|----------|--------|---------|
| [`/authorize`](/api-reference/oauth/authorize) | GET | Start OAuth authorization flow |
| [`/token`](/api-reference/oauth/token) | POST | Exchange authorization code or refresh token for access tokens |
| [`/userinfo`](/api-reference/oauth/userinfo) | GET | Get user information (email, name) |
| [`/introspect`](/api-reference/oauth/introspect) | POST | Validate and inspect tokens |
| [`/revoke`](/api-reference/oauth/revoke) | POST | Revoke access or refresh tokens |

## Agent Back-Channel Endpoints

Endpoints used by agents to authenticate via back-channel:

| Endpoint | Method | Purpose |
|----------|--------|---------|
| [`/api/agent/authenticate`](/api-reference/agent/authenticate) | POST | Authenticate agent and create authorization code |
| [`/api/check-status`](/api-reference/agent/check-status) | GET | Poll for authorization status |

## Admin Endpoints

Administrative endpoints for managing resources (requires admin authentication):

| Endpoint | Method | Purpose |
|----------|--------|---------|
| [`/api/admin/agents`](/api-reference/admin/agents) | POST | Create new agent |
| [`/api/admin/agents`](/api-reference/admin/agents) | GET | List all agents |
| [`/api/admin/clients`](/api-reference/admin/clients) | POST | Register new OAuth client |
| [`/api/admin/clients`](/api-reference/admin/clients) | GET | List all OAuth clients |
| [`/api/admin/clients/update`](/api-reference/admin/clients-update) | POST | Update OAuth client |

## Discovery Endpoints

OAuth server metadata and key information:

| Endpoint | Method | Purpose |
|----------|--------|---------|
| [`/.well-known/oauth-authorization-server`](/api-reference/discovery) | GET | OAuth 2.0 server metadata |
| [`/.well-known/jwks.json`](/api-reference/discovery) | GET | JSON Web Key Set |

## Rate Limiting

Currently, Auth Agent does not implement rate limiting. This may change in future versions.

## Error Responses

All endpoints follow standard OAuth 2.0 error response format:

```json
{
  "error": "invalid_request",
  "error_description": "Missing required parameter: client_id"
}
```

### Common Error Codes

| Code | Description |
|------|-------------|
| `invalid_request` | The request is missing a required parameter or is malformed |
| `invalid_client` | Client authentication failed |
| `invalid_grant` | The authorization code or refresh token is invalid or expired |
| `unauthorized_client` | The client is not authorized to use this grant type |
| `unsupported_grant_type` | The grant type is not supported |
| `invalid_scope` | The requested scope is invalid or unknown |
| `server_error` | Internal server error occurred |

## Security

<AccordionGroup>
  <Accordion title="PKCE Required">
    All authorization flows must use PKCE (Proof Key for Code Exchange) with the S256 method. Plain code challenges are not supported.
  </Accordion>

  <Accordion title="HTTPS Required">
    All redirect URIs must use HTTPS, except for localhost development. HTTP is only allowed for localhost URLs.
  </Accordion>

  <Accordion title="Token Rotation">
    Refresh tokens are automatically rotated on each use. When you use a refresh token to get new access tokens, the old refresh token is revoked and a new one is issued.
  </Accordion>

  <Accordion title="Secure Secrets">
    All secrets (agent secrets, client secrets) are hashed using bcrypt with 10 rounds before storage. Never share your secrets in client-side code.
  </Accordion>
</AccordionGroup>
